# Web／iPhone比較の整理根拠

2026-11-16。結果だけでなく、入力・抽出方法・採否・確認方法を再現できる形で保持する。

## 目的と判定

「送れる」は、受け手で内容を見たり利用したりできること。文字列やファイル名の到着だけで図・画像・動画を○にしない。PC外はWeb共有画面とiPhone PWA。往路はPC→PC外、復路はPC外→PC。

2026-11-17追記：機能ツリーの要求/機能/ソースのテスト対応追加後、元の71機能の名前と順序が同一であることを照合し、正本hashを更新した。

## 元にした資料と抽出方法

- 母集団：[機能ツリー](000_FEATURE_TREE.md)第1部の実現案71件。第2部のテスト表を機能数に加算しない。本文中の下位機能は対応仕様・実装で補う。
- 正本SHA256：`404a62e756c38a5a764d64923c19d36138d9782ce2242cefce49fb6c8d18dde3`。
- 抽出：第1部を要求ごとに読み、太字の実現案を列挙。生成結果の内容、付箋属性、送信経路・通知、PC内の操作・管理を仕分ける。
- 例：キャプチャ／貼付／描き込み／切り取りは、送られる結果が静止画なので集約する。ホットキーそのものを送信可否の行にしない。
- 「iPhoneからPCへ送る」の下位にある動画・汎用ファイルは、003_IPHONEと実装から補う。マスターの太字ノードだけを送信物の全種類とみなさない。
- 機能ツリーにない勝手な製品要求は追加しない。未確認を×や○で埋めない。

|画像倍率・文字サイズ・透明度|PC固有表示と移送する内容の区別が必要|相手側の同一表示は未検証。代表表示へ載せない|
