# 俺の付箋 ドキュメント・デザインシステム & 品質チェックリスト

このドキュメントは、「なぜそのように書くべきか」という客観的な理論（第1部）と、実際のVitePress移行作業において「ルールが守られているか」を判定するための具体的な100項目のテストリスト（第2部）の2部構成になっています。

# 【第0部】ドキュメントのMVP（最終的に提供する価値）

すべてのルールやデザインパターンは、以下の「たった一つの目的」と「3つの価値基準（MVP）」を達成するために存在します。もしルール適用の判断に迷った場合は、このMVPに立ち返ってください。

> **究極の目的：「すべては、読む人に優しく！」**
> ドキュメントは単なる仕様の羅列ではなく、未来の開発者やチームメンバーへ向けた「親切な案内状」でなければならない。

### 1. わかる (Understandable) — 「迷わせない・脳を疲れさせない」
*   **提供価値**: 読者が「いまどこにいて、次に何を読めばいいか」を瞬時に理解でき、システム変更時の「なぜこう作ったのか」というコンテキスト（背景）を確実に受け取れること。
*   **支える理論**: ミラーの法則（5±2のチャンク化）、ヒックの法則（INDEXの導線）、USDM（理由の言語化）。

### 2. きれい (Beautiful) — 「直感的に意味が伝わる」
*   **提供価値**: テキストの海から重要な情報を探し出す苦労をなくし、警告や補足、要件のステータスが「見た目（色や枠）」だけで本能的に伝わること。
*   **支える理論**: ゲシュタルト要因（Noteの色分け）、図と地の法則（USDMバッジ）、シグニフィアンス（表のNo通番）。

### 3. たのしい (Fun) — 「読んでいて飽きない・メンタルモデルが浮かぶ」
*   **提供価値**: 文字ばかりの退屈な仕様書から脱却し、図解や適切なUIを通じて、システム全体の動きが脳内にありありとイメージできる心地よい体験を提供すること。
*   **支える理論**: Fの法則（見出しアイコンと要約）、二重符号化理論（Mermaid図解による視覚とテキストの融合）。

# 【第1部】ドキュメント・デザインシステム（理論と実践）

上記のMVP（わかる・きれい・たのしい）を実現するための、人間の認知特性やUI/UX原則に基づく明確な根拠と実践ルールです。

## 1. 情報アーキテクチャと認知負荷（「わかる」の実現）
*   **ミラーの法則（7±2）**: 人間が一度に処理できる情報量には限界があります。巨大な1ファイルにまとめず、000〜006のように関心事ごとにファイルを分割（チャンク化）し、脳のメモリ溢れを防ぎます。
*   **ヒックの法則 / Diátaxis**: 選択肢が多いほど意思決定は遅れます。INDEX（ポータル）を設け、「全体像」と「読む順序」を明示して読者の導線をコントロールします。

## 2. 要求仕様と情報の書き方（「わかる・たのしい」の実現）
*   **USDM原則**: 要件は「要求」「理由」「仕様」に分離します。特に「理由（Why）」が欠落すると未来の変更時にコンテキストが失われるため、絶対に省略しません。
*   **Fの法則**: 見出しの左端に適切なアイコンを、直下に短い要約を配置します。これにより、読者が斜め読み（スキャン）した際に、0.1秒で自分に必要な情報かを判断できます。

## 3. 視覚表現とレイアウト（「きれい」の実現）
*   **ゲシュタルト要因（類同・近接）**: 補足や警告はただのテキストにせず、青（Info）・黄（Warning）・緑（Success）・赤（Danger）の「Noteブロック」として視覚的に分離し、本能的に意味を察知させます。
*   **図と地の法則**: 要求ID（`[REQ_01]`）などを「バッジUI」で囲むことで、テキストの海（地）から重要な情報（図）を浮かび上がらせます。

## 4. 図解・表組み（「きれい・たのしい」の実現）
*   **シグニフィアンス**: すべての表の1列目には「No（通番）」を振り、「レビューで指定可能なインデックスである」というサインを出します。
*   **二重符号化理論**: テキストの羅列ではなく、Mermaidで視覚的な図解（アーキテクチャやフロー）を添えることで、読者の脳内に正しいメンタルモデルを定着させます。
