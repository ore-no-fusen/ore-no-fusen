# 計画書：付箋の透明化（右クリックで3段階）

作成日: 2026-06-17
最終更新: 2026-06-17
対象バージョン: v4.0.2 ベース
状態: **設計確定（実装に進める）**

---

## 1 目的

付箋を**半透明にして、下の画面が透けて見える**ようにする。
背景の作業（コード・ブラウザ等）を隠さずに、付箋を「うっすら重ねておく」使い方ができる。

右クリックメニューから**3段階**で選べるようにする。色変更と同じ操作感。

---

## 2 仕様（確定した部分）

### 2.1 3段階の透明度
| 段階 | 表示名 | 不透明度 | 見え方 |
|------|-------|---------|--------|
| 1 | 不透明 | 100% | 今までどおり。完全に見える |
| 2 | うすめ | 70% | 背景がうっすら透ける。文字はしっかり読める |
| 3 | かなり透ける | 40% | 背景がはっきり透ける。文字はまだ読める |

- ％は実装後に実物を見て微調整してよい（初期値）。
- Windows API はα=0〜255。100%=255 / 70%≒179 / 40%≒102。

### 2.2 付箋ごとに保存（確定）
- 透明度は**付箋ごと**に持ち、frontmatter に保存する（色・位置と同じ扱い）。
- アプリを閉じて再起動しても、その付箋の透明度が保たれる。

### 2.3 起動方法（UI）
- 付箋の**右クリックメニュー**に「透明度」サブメニューを追加（色変更メニューの近く）。
- 中に「不透明／うすめ／かなり透ける」の3項目。色変更と同じ作りにする。

---

## 3 実装方針（状態管理の鉄則に沿う）

唯一の状態は Rust `AppState` / frontmatter。フロントは表示と invoke のみ。

### 3.1 透明度の適用（既存の土台を流用）
- 付箋ウィンドウは既にレイヤードウィンドウで、`SetLayeredWindowAttributes(hwnd, COLORREF(0), α, LWA_ALPHA)` で
  透明度を操作している（`src-tauri/src/lib.rs` の Pool 昇格処理。現在は α=0↔255 の2値）。
- これを **任意のα値**で呼べるようにし、3段階の値を渡す。
  - 注意（既存コメント）: 透明のままフォーカスを取ると1文字目が消えるバグがある。
    α設定はフォーカス取得より**先**に行う既存順序を壊さない。

### 3.2 frontmatter への保存
- `backgroundColor` や `folded` と同じパターンで **`opacity` キーを1つ足す**。
  - 生成: `generate_frontmatter`（`logic.rs`）に opacity 行を追加
  - 読取: `extract_meta_from_content`（`logic.rs`）の正規表現に `opacity` を追加
  - 値の形式は実装時に決める（例: `opacity: 70` のように百分率、または 0.0〜1.0）
- 既存付箋（opacity キーなし）は **100%（不透明）扱い**にフォールバック。

### 3.3 適用タイミング
- メニューで選んだ瞬間に: ①ウィンドウのαを変更 → ②frontmatter に保存
- 付箋を開く（ウィンドウ生成）時に: frontmatter の opacity を読んでαを適用

## 4 関連する作業ルール
- **データを壊さない**: 本文・タグ・色・位置を壊さず、opacity キーだけ足す。
- **テストとセット**: opacity のパース（`extract_meta_from_content`）と生成のテストを Rust 側に追加。
- **既存付箋の互換**: opacity 無し → 100% にフォールバックするテストを入れる。
- **i18n**: メニュー文言（不透明／うすめ／かなり透ける）を `lib/i18n.ts` に ja/en 追加。
- **ブランチ運用**: frontmatter スキーマと Rust に触る＝アプリに影響する変更。
  小〜中規模。`develop` 直接か小さい作業ブランチで。整列とは独立タスク。

## 5 論点（確定）

### 5-1 opacity の保存フォーマット（確定: 案B）
- **`opacity: 0.7` 形式（0.0〜1.0）** を採用。CSS の opacity と揃い、α計算（×255）も素直。
- 3段階の保存値: 不透明=`1.0` / うすめ=`0.7` / かなり透ける=`0.4`。
- 範囲外・壊れた値（負数・1超・非数値）は **1.0（不透明）にフォールバック**。
- 既存付箋（opacity キーなし）も **1.0 扱い**。

### 5-2 「ロックだぜ（最前面）」との相互作用（テストで確認）
- 最前面表示中の付箋を透明にしても操作できるかを確認する。
- クリック貫通（透明部分で下のウィンドウを触れる）が起きないか確認する
  （α透明は通常クリック貫通しないが、念のため）。
- 確認方法: 実装後に **実機 + 必要なら自動テスト**で検証（ユーザー方針）。
