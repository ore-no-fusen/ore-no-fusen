# お気に入りにしまう：現在の方針（2026-10-08）

## 通常版の調査結果
- お気に入り登録はshortcutタグを付けるだけで、画面から消さない（useStickyNoteContextMenu.handleToggleShortcutShelf）。
- 全隠しの付箋は、ランチャーの既存open_note経路で再表示できる。
- 1枚を意図的に「お気に入りにしまう」操作・状態管理はない。
- フォルダー収納はArchive/タグフォルダーへ移動する別操作。クイックランチャーへ統合しない。

## 最新のユーザー意図
画面からなくす操作には3段階ある: 不要なら削除、保管ならフォルダー収納、頻繁に呼ぶものはお気に入り収納。
まずお気に入りに登録し、その後ランチャーの各行のボタンでしまう/取り出す。
お気に入り登録だけでは画面から消えない。

## 実装範囲
- ランチャーは既存の4タブを維持。
- お気に入りの各行に表示状態と操作を設ける: 表示中→「しまう」、収納中→「取り出す」。
- 登録はどちらの操作でも残す。対象はshortcut登録された通常付箋だけ。QA/用語/手順は既存の返却操作を維持。
- しまう: その窓の最新本文/画像参照/位置/大きさを保存→収納状態を保存→演出→画面から消す。保存失敗時は画面に残す。
- 取り出す: 同じ付箋を表示。重複窓を作らず、表示成功まで収納状態を解除しない。
- 再起動でもお気に入り収納を維持する。全表示/整列で意図せず出ないようにする。
- 収納中の登録解除の扱いは、アクセスを失わないよう復帰させる案を実装時に確定する。削除扱いにはしない。
- データは移動しない。通常フォルダー収納・ゴミ箱・画像復元を変更しない。
- 全フォルダー収納をランチャーへ統合する旧案と、未登録の通常付箋まで新方式で収納する旧案は採用しない。

## 検証する結果
登録だけでは見えたまま / しまうと1枚だけ消える / 登録一覧には残る / 同じ行から取り出せる。
編集途中の本文・画像を保持 / 保存失敗で閉じない / 連打で重複窓を作らない / 再起動・全表示で勝手に出ない。
お気に入り解除・外部のファイル移動・画像パスについて取り出し不能にしない。
行ボタンの操作が行クリックの「開く」へ伝播しない。

## 2026-10-08 追加指示と実装
ユーザー回答によりタグ全体の収納はお気に入り未登録も対象とする。お気に入りは自動登録しない。既存4タブを維持し、お気に入り内の「しまった付箋」に通常付箋の画面収納一覧を設ける。フォルダー収納一覧とは統合しない。タグ全体は現在のデスクトップ付箋を対象とし、検索やお気に入り登録には限定しない。
対象窓で最新編集を保存して収納・演出・hideの完了を待つ。15秒応答待ち、期限切れ要求の収納拒否、二重操作防止。失敗分は画面に残して表示する。トレイ入口も追加。
作業場所は引き続き.w/タスクバーランチャー。通常起動中アプリは変更していない。
