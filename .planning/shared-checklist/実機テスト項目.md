# 共通付箋の実機テスト項目

更新日: 2026-10-17
目的: Windowsのクイックランチャーに登録した付箋を、Windows/Mac/Android/iPhoneのWebブラウザーで見て、Web側の変更をWindows原本へ安全に戻せるか確認する。

## 今回確認する機能と同期方向

```text
Windows付箋 ──［Windowsランチャー: Webと同期］──▶ Google Drive ──［Webを開く/更新］──▶ Web表示
Web編集 ──［保存］──▶ Google Drive ──［Windowsランチャー: Webと同期］──▶ Windows付箋
```

| 機能 | 操作する場所 | 同期方向 | 確認すること |
|---|---|---|---|
| 登録付箋をWebへ送る | Windowsランチャーの「Webと同期」 | Windows → Drive → Web | 登録した付箋の本文・チェック・画像がWebで見える |
| Webで見る | Windows/Mac/Android/iPhoneのブラウザー | Drive → Web | 同じGoogleアカウントなら同じ付箋が見え、別端末でも表示が一致する |
| Webで編集して保存 | Web画面の「編集」→「保存」 | Web → Drive | 保存後にWebを更新すると変更が見える。Windows原本はこの時点ではまだ変わらない |
| Web変更をWindowsへ戻す | Windowsランチャーの「Webと同期」 | Drive → Windows | 同期後にWindows原本へ反映する。競合があれば自動上書きせず保留する |
| 変更なしの再同期 | Windowsランチャーの「Webと同期」 | 送受信なし | 同じ内容を何度も送らず、結果が「変更なし」になる |

**自動同期ではありません。** Webを開いただけではWindowsへ戻りません。Webの「Webを更新」はDriveからWeb画面を読み直す操作です。Windows原本へ反映する操作はWindowsランチャーの「Webと同期」です。

## いまのWeb画面でできること・制限

| 表現/機能 | 現在の扱い | 試験・判断 |
|---|---|---|
| 普通の文章・改行 | 表示/編集/保存できる | 改行がWindowsへ戻っても保たれることを確認 |
| チェック項目 | 編集モードでチェック・項目編集でき、保存後にWeb/Windowsへ同期する | R3/R4で確認 |
| 画像 | Drive共有画像をWebに表示できる。画像データ自体のWeb編集は対象外 | R1/R2で1枚表示を確認 |
| 付箋の色 | Windowsの許可色を共有データへ含め、Webの付箋面と一覧マーカーに反映する実装中 | R1/R2でWindowsと同じ色か確認。旧データは黄色を既定表示 |
| タイトル | 一覧と付箋見出しに表示。同じタイトルが本文先頭にある場合は閲覧時のみ重複を隠す | R3で確認。保存本文は削らない |
| 太字・見出しなどのMarkdown装飾 | 太字、見出し、箇条書き、番号付き項目を表示する | Windows表示と同じ見え方か実機で照合する |
| Mermaid図 | 図として描画する。失敗時はコード表示へ戻る | 実機ブラウザーで図と横スクロールを確認する |
| Webから新規付箋作成 | いまの実装に含まれない | 後続機能。実機テスト対象外 |

**今回の合格範囲:** まず「登録した付箋を見られる」「本文/チェックをWebで変更して保存できる」「Windowsの同期ボタンで原本へ戻る」「画像と色が見える」を確認します。太字・Mermaid描画・Web新規作成は、対応段階を分けて確認します。

**このテスト範囲でできない操作:** Webから新しい付箋を作ってWindowsへ登録する機能は、実機テスト対象に含めない（画面・実装がそろってから別項目に追加）。Windows付箋の画像をWebで表示する確認は対象。

## 実施前の準備

1. 開発版を通常の手順で起動し、共通Web画面 `/shared` が開くことを確認する。
2. 検証用Googleアカウントでサインインする。全端末で同じアカウントを使う。
3. 実データを使わず、Windowsで専用の架空付箋を1件作る。例: タイトル「実機試験」、本文「あいうえお」、チェック項目「牛乳」、画像1枚。
4. その付箋だけをクイックランチャーに登録する。試験対象外の付箋は変更しない。
5. 画面・同期結果・開始/終了時刻を記録する。失敗時は同じ操作を連打せず、画面を保存して止める。

## 開始条件と現在の制約

この表を使った実機再試験は、共通Web画面を基本のdevelop環境へ統合し、開発サイトの `/shared` が起動できてから行う。作業ワークツリーの画面が開けても、普段の開発環境で試験合格した扱いにはしない。実機でR1〜R9を確認するまではリリース可とは判定しない。
