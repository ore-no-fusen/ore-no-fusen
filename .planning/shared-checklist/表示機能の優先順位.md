# 共通Webの表示をWindows付箋へ近づける計画

更新日: 2026-10-17

## 目的

今回の主目的は、Windowsで見ている付箋をWebでも同じように見られること。まずWindows→Webの表示だけを優先する。Webで編集してWindowsへ戻す下り同期は重要度を下げ、後続段階で扱う。付箋本文の原本はMarkdownなので、本文を書き換えずにWeb側のMarkdown描画を整えれば、強調・見出し・箇条書きなどをWindowsに近い見た目で表示できる見込みが高い。Google Driveは一時共有場所、Windows付箋は原本、同期は利用者が押した時だけという既定方針を維持する。同期データに含まれることと、画面上で同じ見た目になることは分けて評価する。

## 優先順位

利用者指定: **No.1〜11はすべて必須**。表の上から順に一項目ずつ実装・確認する。最初の完成目標はWindows→Web表示で、Web→Windowsへ変更を戻す下り同期は後回しとする。「必須」は順番に揃える機能であり、一度に全部を実装する意味ではない。

### No.1〜3の共有形式に関する先行条件

- 色と表示用タグをpayloadへ追加する前に、共有データ形式の版とhash protocolの互換方針を決める。
- 既存記録は旧版として読み、旧hash検証を維持する。旧記録に色/タグがない場合は既定色/空タグとする。
- 新版は固定されたフィールド順でhashし、RustとTypeScriptの共通fixtureで同じhashになることを確認する。
- 旧v1同期基準からv2へ移る際、Windows本文・タイトル・画像に変更がなく表示メタデータだけが追加された場合は、形式更新だけを競合と誤判定しない。コンテンツ本体に差がある場合は従来どおり保留する。
- 色はアプリで許可されている色値だけを共有する。タグは表示/絞り込みに必要な通常タグだけを共有し、予約タグやローカルパスなどは含めない。
- No.2の検索とレイアウトを先に作り、No.3でタグの取得・絞り込みを完成させる。

## 上から順に進める工程

利用者指定によりNo.1〜11はすべて必須です。一項目ずつ実装・確認してから次へ進みます。まずWindows→Webの表示を完成させ、Web→Windowsへの変更反映は後段です。

1. No.1 付箋の色をWindowsと同じにする（まず上り表示）。
2. No.2 ランチャー風に、タグ/検索、一覧、選択中の付箋内容を同じ画面に配置する。
3. No.3 Windowsのタグを上りで共有し、Webで読み込み済みデータを絞り込む。タグ選択のたびにDriveへ問い合わせない。
4. No.4 画像の比率・大きさ・複数枚・スマホ表示を確認する。
5. No.5 チェック項目の表示をWindowsに寄せる。
6. No.6 本文・改行・長文の折返しを整える。
7. No.7 太字などのMarkdown強調を表示する。
8. No.8 見出し・箇条書きなどMarkdownの構造を表示する。
9. No.9 タイトルの重複と見せ方を揃える。
10. No.10 Mermaid図を表示し、スマホでも読めるようにする。
11. No.11 リンクとコードをWebで安全に表示する。
12. 後続工程として、Webでの編集変更をWindowsへ反映する範囲を広げる。

### Markdown描画とMermaidの安全条件

- Markdownは読み取り表示時だけ描画し、Windows原本のMarkdown文字列は変更しない。
- HTMLは無効化する。リンクは `https:` と `http:` のみ許可し、`javascript:` 等はリンクとして扱わない。
- 共有manifestで検証できた画像だけを表示する。コードフェンスやインラインコード内の画像/リンク/強調記号は構文として解釈しない。
- Markdown描画導入後は、本文・改行・チェック・画像が混在したfixtureを各段階で再確認する。
- Mermaidはクリック等のイベントと外部参照を無効化し、入力長/描画時間に上限を設ける。描画失敗時は図を壊れたHTMLとして出さず、コード表示へ戻す。複数図・長い図・狭い画面で確認する。
## 完了の判定

- Windows画面とWeb画面を同じ架空付箋で並べ、各項目を「同じ」「読めるが見た目が違う」「未対応」で判定する。
- No.1〜11を一つずつ実装・確認する。最初の完了条件はWindows→Webの表示。下り同期は別枠として記録し、上り表示の完了を妨げない。
- 画像/色/Markdownの表示対応を、データ同期の対応済みと混同しない。
- 文字、画像、チェック状態、タグ、色が欠落しないこと。スマホで一覧/本文を操作できること。表示の都合で原本Markdownを書き換えないこと。
- No.2はタグ以外の一覧/検索/選択表示、No.3でタグ絞り込みまでを合格条件とする。「読めるが見た目が違う」は差を記録し、No.1〜11の完了扱いにしない。
- 変更ごとに自動試験を追加し、基本フォルダーへ統合した後にPC・Android・iPhoneの実画面で確認する。

## ソース確認上の根拠

- 共有payload v2はタイトル、Markdown本文、画像manifest、許可色を含む。タグはNo.3で追加する。既存v1 payloadは従来どおり読み込み、色の既定値を黄色にする。ウィンドウ配置等は共有しない。
- Windows Quick Launcherは付箋ごとのtagsを保持し、タグ選択による絞り込みと検索がある。共通Webの現行一覧は付箋選択/詳細表示はあるが、タグフィルター/検索UIがなく、共有payloadにもタグがない。
- Web→Windowsは本文の反映が中心。タイトル変更と画像manifestの差分は保留される。
- 現在の共通Web画面は本文、チェック項目、共有画像を表示する。共通Web用のMarkdown装飾描画はまだない。
- Windows `MarkdownRenderer` とiPhone PWA `SimpleNoteBody` には、太字/見出し等またはMermaid描画の既存処理がある。ただしWindows専用機能への依存を調べず、そのまま共通Webへ移植できるとは見なさない。
