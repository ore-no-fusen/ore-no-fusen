# Astra設計レビュー（2026-10-19）

対象: Web追加削除計画、iPhone既存入力/下書き/送信/削除、共有契約、未コミットpathUtils表示更新修正。コードと資料の静的レビュー。Astra自身は自動試験・実機試験を実施していない。

判定: 段階順は妥当。以下を詳細設計で確定するまで新規作成/削除実装に着手しない。

| 重要度 | 指摘 | 対応方針 |
|---|---|---|
| BLOCK | 所有PCと一度だけの取り込みが未確定 | account/noteId/作成operationIdを送信前に永続化。原本作成→登録→受領の中断復旧を定義 |
| BLOCK | 非表示・共有解除・原本アーカイブの区別と世代競合が未確定 | 3操作を区別。復元は新世代。対象本文版と世代を固定し未保存/競合は保留 |
| HIGH | 旧版は新操作を理解できない | 対応版判定、旧版書込停止または領域分離、未知操作で原本を変更しない条件を定義 |
| HIGH | iPhone下書き/送信をそのまま流用できない | 送信ごとの新ID・配列更新の競合、3秒自動保存と失敗黙殺を改善。アカウント別下書きと段階別保存表示 |
| HIGH | 画像・復元の保全 | blob/manifest/本文参照が揃うまで作成確定しない。競合枝/旧世代/復元期間の画像保持 |
| HIGH | 長文構造編集の原文保持が未合格 | 新規着手前に見出し/改行/チェック/コード/画像をまたぐ編集と下り表示更新を実機確認 |

iPhoneの削除済みIDは端末内IndexedDB・500件上限で、端末横断の解除や原本削除には使えない。iPhoneの入力UXと保全の考え方は応用し、共有同期契約は別途設計する。

最低試験: 応答消失再送/二重タップ/2タブ、複数PC所有権、原本保存後/登録後/受領前中断、解除後遅延編集と新世代復元、未保存との競合、旧版混在、オフライン/認証切替/画像欠落/容量不足、実ブラウザー→Drive→通常Windows付箋。

pathUtilsのdrive/UNC拡張接頭辞正規化と等価/別ファイル/reload listenerの回帰試験には重大懸念なし。ただし静的レビューであり実機合格ではない。

採否: 全指摘を採用。計画へ実装前条件を追記済み。所有PC/互換/復元の詳細契約確定、原文保持の原因切分けと実機再試験は未完了。
