# クイックランチャー付箋 Web共有 — 実装・試験計画

2026-10-14 / 利用者確認済み画面・シーケンスを基準にした実装計画。Astra追レビューを受け、未完了のライブ試験と安全ゲートを分離して実装を開始する。

## 1. 固定する価値観と初版の動き

- Windowsが付箋の原本。Google Driveは、ランチャー登録中の付箋をWebで共有するための置き場。
- iPhone連携を優先し、その必要枠と予備を先に確保する。Web共有は残りの枠を使う補助機能。
- 自動同期は初版に入れない。Windowsからはクイックランチャーの「Webと同期」を押した時だけ送受信する。登録していない付箋には触れない。
- WebはiPhone/Android/Windowsのブラウザーで共通。読む時はページを開く/「表示を更新」、Web変更は「編集」→本文/チェック変更→「保存してDriveへ反映」。閲覧中のチェックは押せない。
- Webで保存した変更はDriveへ新しい変更記録として追加し、Windows母艦で「Webと同期」を押した時だけWindows原本へ反映する。既存のDrive本文を直接上書きしない。Web画面にWindows同期ボタンは置かない。
- 付箋ごとに変更元を比較する。片側だけの変更は反対側へ反映し、両側で変更された付箋は両方を保全して確認待ち。利用者が選ぶ前に上書きしない。
- 端末のバックグラウンドpolling、push通知、中継サービス、編集ごとの自動送信は初版対象外。

## 4. 実装順と各段階の試験

### A. 仕様・契約を固定（この文書とAstraレビュー）

- 画面/シーケンス/本計画に矛盾がないかAstraにレビュー依頼。
- Astraの指摘を反映して再確認し、重大指摘が残らない状態で次へ進む。
- 合格: 編集・チェックの保存手順、Windows同期ボタン、競合時動作、手動更新タイミング、Drive/Vercel見積もりの条件が一貫する。

### B. データ形式・競合保存の実接続試作（安全ゲート）

- 安定した共有付箋ID、アカウント単位のID対応分離、原本パスとの対応、版番号/変更ハッシュ、画像manifest所属確認、Windows反映済み版を定義。
- Markdownの見出し/チェック/画像を往復し、frontmatterやローカル画像パスを漏らさず保つ。
- Drive metadataと本文取得でETagが返らない試験結果を記録し、version番号だけを原子的な比較更新の保証として扱わない。条件付き更新は未確認で、採用前提にしない。
- 暫定候補は変更ごとに一意ID・親revision・baseVersion・変更元を持つ不変の変更記録をDriveへ新規作成する方式。Windows/Webが同じ版から同時に保存した試験では別記録2件を保存し両方再取得できた（Drive API 9回/試験画面表示。単一回の小規模試験であり、quota unitsではない）。これは製品採用の確定ではない。
- 操作記録の契約を定義する: account subject, noteId, shareGeneration, operationId, payloadHash, parentOperationIds, sourceDevice, deviceSequence, imageManifest。Driveのversion/modifiedTimeを因果順に使わない。全ページをnextPageTokenがなくなるまで読み、親存在・世代一致・manifest一致を検証してから候補を読む。
- 親子DAGを構成し、ACKを探索の切断点にしない。世代内の全取得済みDAG、Windows適用済み先端、未送信Windows変更から競合を判定する。利用者の解決も全先端IDをparents/resolvedIdsへ列挙する新しい操作として保存する。解決後に旧枝の子が届いたら自動適用せず保留。
- DAGのroot IDはaccount subject/noteId/shareGenerationからWindows側が導出し、任意の`root:`文字列を受け付けない。本文変更はscopeと親がすべて検証された時だけ先端候補にする。ACK/解除は制御記録として別評価し、本文先端や有効世代を単独で進めない。
- payloadHashの正規化対象はaccount subject、noteId、shareGeneration、正規化した親ID集合、本文/チェック等のpayload、画像manifest。operationIdが同じでhash一致なら論理上1回、異なるhashなら拒否。deviceSequenceは診断用のみで因果順に使わず、再インストール時は新sourceDevice IDを発行する。
- 解除はshareGenerationを進める記録で旧世代操作を採用しない。Web一覧/通常取得から隠す処理と、未解決枝・遅延操作・参照画像の隔離保全を分ける。解除済み世代の遅延操作は黙って捨てず回収対象にする。初版では自動整理を行わず、容量上限で新規保存を停止する。
- Drive保存済みは記録の保存だけを意味する。Windows ACKは世代と適用済みoperation IDsを含む。未解決枝・未取得ページ・不足画像があれば同期完了を示さない。
- Astra再レビューの指摘は暫定仕様/試験へ反映済み。未解決の設計詳細は製品採用前に再レビューする。満たせない場合は条件付き更新を再調査するか、API/DB方式へ戻す。
- 試験: 二枝を逆順受信、AをWindows適用/ACKした後に兄弟枝Bが到着、A適用後のWindowsローカル編集に続いてB到着、解決後に旧枝の子を到着、同一ID同一hash再送/同一ID異hash、応答消失後の再送、長期未同期端末復帰、解除中の遅延保存と再共有、ページング欠落/親不明、画像未完了/共有解除後の参照、ACK欠落、容量上限到達時の書込停止と容量停止中のACK/解除/競合解決の失敗表示・再試行。
- Web同士とWeb対Windowsで、同時保存、保存応答消失後の再送、同じoperationIdの重複排除、古いrevision、長期未同期の変更を試す。
- 試験: 新規/既存/改名/移動/削除、複数チェック、空本文、日本語/絵文字、画像あり、未知frontmatter、変換失敗。
- 進め方: Bの未実施項目が残っていても、隔離された純粋モデル、Web画面、ローカル保存/変換のテスト可能な実装を進める。これはDriveライブ試験の合格を意味しない。
- 停止ゲート: WindowsがDrive上の変更を原本へ適用する機能、および利用者向け配信は、同一ID再送・親/世代検証・解除時保留・欠落画像/容量停止・noteId二重作成防止・クラッシュ再開・iPhone予算を先取りした実units確認・最終Astraレビューが完了するまで有効にしない。
- 合格: アカウント切替で別利用者のID/内容を混ぜず、画像は有効manifestに紐づくものだけ返す。初版は自動整理をしないため、容量上限で安全に停止できることも出荷条件。

### C. Windows「Webと同期」

- ランチャー登録付箋だけ一覧化し、初回は共有用データを作り、2回目以降は差分のみ送受信。
- Drive変更記録の親子DAGとWindows原本を比較し、競合なしのWindows変更だけを不変記録で追加する。Web変更適用後はoperation IDs/世代を持つACK記録を追加する。
- 試験: 登録/未登録混在、登録解除、変更なし、PCのみ変更、Webのみ変更、Web追加、同期中二重クリック、途中通信失敗、再起動後再試行。
- 通信観測: 新しいWeb共有経路では同期ボタン押下前に要求0、押下時のみ発生。既存iPhoneの30秒受信通信は別経路として継続し、同期ボタンの前後で退行がないことを確認。初回/差分/再試行の要求数・units・bytes・画像量を記録し、上限値を明記。
- 合格: 未登録を送らない。失敗後の再試行で重複やデータ巻戻りなし。成功表示は実際の保存/適用完了後。
- 追加試験: 登録解除はローカル操作だけではWebから消えず、次のWindows同期時に共有を解除する。取り込み処理と、既に開いていた古いエディタの遅延保存が競合してもWindows変更を巻き戻さない。
- クラッシュ試験: Web追加の「Markdown作成→ランチャー登録→Drive ACK」の各地点でPC処理を中断し、再起動後に同じnoteIdを再利用して一度だけ完了する。

### D. 共通Web画面

- iPhone/Android/Windowsブラウザーで一覧、詳細、検索、画像、追加、編集、保存、表示更新を提供。
- 閲覧時はチェックを操作不可にし、「編集」後だけ本文/項目/チェックを編集可能にする。
- 「保存してDriveへ反映」はDriveへWebの変更記録を追加し、Windows原本は更新しない。Windows取込待ちを表示。別枝があればDrive保存済みでも競合確認待ちを表示。
- 試験: 保存前キャンセル、保存成功/失敗、連続チェック編集、表示更新、端末別狭幅/広幅、画像表示/拡大、ログアウト/期限切れ、未保存警告。
- 認証・設定試験: アカウント切替時に前のID対応を再利用しない。画像IDが現役manifestに属さない時は拒否。予算設定が未取得/古い場合は警告と再取得案内を表示し、中央強制停止を保証する表示を出さない。同期あたり要求数の上限はB/Cの実測から設定する。
- 表示更新試験: 編集中に「表示を更新」を押した場合、未保存確認を出して再読込を止めるか、未保存内容を保持したまま更新を拒否する。
- 合格: 編集モードにしなければチェックを変えられない。保存成功を偽らない。Webの再表示は利用者の操作時だけ。
- 実装条件: 端末切替ボタンはWeb画面を開くだけのモック機能。本番画面には不要。実画面の「表示を更新」中に未保存変更があれば確認を出し、破棄の同意がない限り再読込しない。

### E. 競合・復旧・アクセス制御

- AだけWindows変更、BだけWeb変更、Cを両方で変更（例: 元「あいうえお」、Windows「かきくけこ」、Web「さしすせそ」）を付箋単位で検出。
- 競合付箋は元/Windows/Webの内容と版を保全し、他の非競合付箋は処理可能。選択前にどれも上書きしない。
- 試験: 同一フィールド競合、異なるチェック項目の競合、同時保存、古いrevision/解決済み枝の遅延子、再送、Driveページング/ACK欠落、解除・再共有、PC停止/再起動。
- アクセス試験: 無認証、別アカウント、共有解除後、削除済み/ゴミ箱画像、直接ID指定、期限切れ認証を本アプリの取得経路で拒否。Drive所有者がGoogle Drive APIで直接取得できるかとは分けて扱う。
- 解除試験: Windowsで登録解除してから同期ボタンを押すまではWeb一覧に残り、同期成功後は本アプリ経由の一覧/画像取得から消える。
- 合格: 部分失敗を明示し、未確定データを保持。他ユーザー/未共有画像を返さない。

## 5. 実装中の必須不変条件

1. Windowsローカル自動保存だけではDrive通信しない。
2. Windows同期は利用者が押した時だけで、Quick Launcher登録付箋だけが対象。
3. Web閲覧中のチェック操作は無効。編集モードの保存でDriveへ書く。
4. Web画面の「表示を更新」はDriveから読み直すだけ。Windowsへの反映は母艦側の同期ボタンだけ。
5. DriveはWindows原本を置き換えない。競合・失敗・未保存のデータを破棄しない。
6. Web追加も次のWindows同期時に一度だけ取り込み、二重作成しない。
7. 初版では編集毎の自動同期、周期polling、push通知、中継サーバーを追加しない。
8. Drive要求数とVercel Function数を別に測る。予算確認APIを同期ごとに追加しない限り、同期用Function 0回の前提を守る。

## 6. 現在の位置
