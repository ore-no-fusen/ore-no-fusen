File is created correctly, but rawFrontmatter stays empty. When user types and handleSave is called, empty frontmatter is sent to Rust, overwriting the original frontmatter with empty content.

expecting: Confirmed - line 775-785 in StickyNote.tsx shows handleFirstChar receives note.frontmatter but never uses it

## Symptoms
expected: File should contain YAML frontmatter with title, created timestamp, and other metadata before the body text
actual: File contains only body text, no YAML header when created on first character
errors: None reported, but frontmatter missing
reproduction: Test 3 in UAT - create lazy note by typing first character in Pool window
started: Phase 19, Test 3 failing

## Eliminated
- Lazy creation calls different endpoint than normal creation: WRONG - both use do_create_note()
- Frontmatter generation is skipped: WRONG - generate_frontmatter() is always called

## Evidence
- Found fusen_create_note_lazy at src-tauri/src/lib.rs:160 calls do_create_note()
- do_create_note (lib.rs:134) creates file with frontmatter generated by build_create_note_data()
- generate_frontmatter() (logic.rs:87) creates YAML with all required fields (title, created, updated, seq, window, backgroundColor)
- File is written with content = "{frontmatter}\n\n{body}" at lib.rs:141
- File creation succeeds and returns Note object with frontmatter field (lib.rs:144-148)
- In handleFirstChar (StickyNote.tsx:761), fusen_create_note_lazy is called and returns note with frontmatter
- CRITICAL MISSING STEP: handleFirstChar receives note.frontmatter but NEVER calls setRawFrontmatter(note.frontmatter)
- handleFirstChar only does: setSelectedFile(note.meta), setDynamicUrlPath(), setIsPool(false)
- Result: rawFrontmatter state remains empty from Pool initialization
- When user types (editBody changes), auto-save triggers handleSave
- handleSave calls saveNoteContent(body, rawFrontmatter, ...) where rawFrontmatter is empty/invalid
- fusen_save_note receives empty frontmatter and overwrites the file content
- handle_save_note (logic.rs:173) uses frontmatter_raw to rebuild file (line 227)
- Empty frontmatter overwrites the valid YAML header created at initial file creation

## Resolution
root_cause: In handleFirstChar callback (app/components/StickyNote.tsx:761-795), after fusen_create_note_lazy successfully creates file with YAML frontmatter, the returned note.frontmatter is never stored in rawFrontmatter state. When user continues typing, auto-save triggers with empty rawFrontmatter, which overwrites the file content and loses the YAML header.
fix: Added setRawFrontmatter(note.frontmatter) at line 782 (after setSelectedFile and before window.history.replaceState). This ensures that when the lazy file is created, the frontmatter from the Rust backend is immediately stored in the React state, so subsequent auto-save calls have the correct frontmatter to preserve.
