# Plan 21-03: winget・既存ユーザー移行・文書同期

## 目的

既存利用者を取り残さず、配布に関する全説明をMSIX正式版へ統一する。

## 作業

1. community packageとStore Product IDの関係を確認し、`winget install --source msstore` を正式手順にする。
2. 旧winget packageの更新停止、説明更新、廃止申請または移行告知を決定する。
3. MSI/NSIS版とMSIX版の設定・付箋・画像の実保存先を検証し、移行手順と重複起動対策を定める。
4. 必要性を検証したうえで、一度限りの旧版向け移行案内（ブリッジ版）を設計する。
5. `docs-v2/008_DISTRIBUTION.md` を正として、ユーザーガイド、トラブルシューティング、README、LP、リリース手順を同期する。
6. 自動起動をWindows側で無効化した場合、Store更新の反映待ち、旧版アンインストール順を説明する。
7. `app/landing/page.tsx` のヒーロー部・最終CTAからGitHub `setup.exe` 導線を除き、Microsoft Storeを主ボタン、Store版wingetを補助導線にする。
8. LPのwingetコピー処理、説明文、アクセシビリティ文言、計測イベントをStore版に合わせる。
9. `app/use-cases/windows-sticky-notes/page.tsx` の本文、コマンド、構造化データ`installUrl`をStore商品ページへ統一する。
10. `app/landing/layout.tsx` のmetadata、`docs/011_VERCEL_SETUP.md`、READMEのバッジ・インストール節・build artifact説明を同期する。
11. `.github/workflows/do-non-app-release.yml` は維持し、Store公開確認後にLPを切り替えるリリース順序を手順化する。
12. READMEのGitHub downloadバッジ2件を削除し、`workers/badges`はreleaseバッジのみ残すか廃止する。旧ダウンロード実績を記載する場合は「GitHub配布時代の累計」と明示する。
13. `docs/012_BADGE_WORKER_SETUP.md` と`workers/badges/README.md`を新しいバッジ構成へ同期する。Partner Centerの取得・インストール数は運用画面で確認し、認証付きStore Analytics APIによる公開バッジは今回の必須範囲に含めない。

## 検証

- 文書内のMSI/NSIS、trial/standard、GitHub installer、旧wingetコマンドを検索監査する。
- VitePress build、リンクチェック、コマンド表記チェックを行う。
- Next.js buildでLPとuse-caseページの静的生成を確認する。
- LPの上下CTAが同じStore URLを指し、GitHub `setup.exe` のリンクが残っていないことをテストする。
- JSON-LDの`installUrl`、metadata、表示文言、コピーされるwingetコマンドの一致をテストする。
- Store商品ページ公開前はLP切替を実行しない手動ゲートを確認する。
- GitHub downloadバッジがStore版の利用数として誤表示されず、旧実績の注記があることを確認する。
- 旧版データを使った移行テストを21-04へ引き渡す。

## 完了条件

wingetと全ドキュメントがStore版を指し、旧版利用者がデータを失わず移行できる手順が確定している。
