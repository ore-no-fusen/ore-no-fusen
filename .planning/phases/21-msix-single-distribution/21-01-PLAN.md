# Plan 21-01: MSIX成果物とStore提出パイプライン

## 目的

5.0.0では移行用のNSIS・MSIを最後に生成しながらStore MSIXを提出し、5.1.0から正式配布物をMSIXだけにできるパイプラインを作る。

## 作業

1. StoreのIdentity、Publisher、Product ID、対応アーキテクチャ、バージョン規則を確定する。
2. 5.0.0では移行案内を含むNSIS・MSIを最後に生成し、同じソースからStore提出用MSIXを構築する。
3. 5.1.0用の切替で`tauri.conf.json`とrelease workflowからMSI/NSISの生成・公開を外し、exe/resourcesからMSIXを1回だけ構築する。
4. release workflow と store-submit workflow のartifact受け渡し不一致を解消する。
5. manifestのidentity、version、capability、asset、署名状態をCIで検査する。
6. GitHub Releaseをリリースノート中心に変更し、未署名MSIXを一般公開しない。

## 検証

- 5.0.0の成果物がNSIS・MSI・Store提出用MSIXの3形式であり、5.1.0の正式成果物がMSIX 1件のみである。
- 展開したAppxManifestと実行ファイルのバージョンが一致する。
- Store提出ジョブが同一runのartifactを取得できる。
- 5.1.0ではMSI/NSIS名のrelease assetが生成されない。

## 完了条件

private/flight提出に利用できるMSIXが再現可能に生成され、旧形式を正式公開しない構成になっている。
