008 — Push デバイス管理機能 設計書

PC の設定画面から push_devices.json の登録済みデバイスを一覧表示・削除できる機能。ゴミエントリの蓄積を解消する。

1. 問題の背景

push_devices.json は iPhone PWA の push セットアップ時に endpoint を追記する。しかし端末の再インストール・PWA の再セットアップ・テスト実行のたびに新しい device_id で追記されるため、古い（無効な）エントリが溜まり続ける。

PC は毎回全エントリにループして Push を送信する。古いエントリは Apple APNs / FCM から 410 Gone が返るが、エラーは無視される。エントリが増えるほど送信コストが増大し、問題の原因特定も困難になる。
2. 要件
ID要件優先度
R-01PC の設定画面で登録済みデバイス一覧を表示できる必須
R-02各デバイスの種別（iPhone/iPad = Apple、Chrome = Google）・登録日時を表示する必須
R-03デバイスを1件ずつ削除できる必須
R-04全件削除できる必須
R-05削除は Drive の push_devices.json に即時反映される必須
R-06削除後、次回の Push 送信から削除したデバイスには送らない必須
スコープ外：Push の到達確認（生死チェック）は今回作らない。エンドポイントが生きているかどうかはユーザーが判断して手動削除する。

4. データ構造

Drive の push_devices.json 構造（現行・変更なし）

{
  "devices": [
    {
      "device_id":      "78ff13d0-d0b3-4e60-95cb-af2fbfaa6240",  // localStorage に永続化された端末固有ID
      "endpoint":       "https://web.push.apple.com/...",         // Web Push 送信先URL
      "keys": {
        "p256dh": "...",  // 暗号化公開鍵
        "auth":   "..."   // 認証シークレット
      },
      "registered_at":  "2026-04-17T21:02:45.496+09:00"          // 登録日時（JST）
    }
  ]
}
フィールド説明書く人消す人
device_idiPhone/iPad の localStorage に保存した UUID。同じ端末が再セットアップしても同じ値になる（localStorage が消えると新規生成）iPhone PWA（subscribePush）PC（削除機能）
endpointAPNs または FCM の Push 送信先 URL。端末ごとに異なるiPhone PWAPC
keysPush メッセージ暗号化に使う鍵ペアiPhone PWAPC
registered_atセットアップ実行日時（参考情報）iPhone PWAPC
5. 処理フロー

5-1. 一覧取得

1
設定画面「通知デバイス」タブを開く → invoke('get_push_devices') を呼ぶ
↓
2
Rust Drive から push_devices.json をダウンロードして devices 配列をそのまま返す
↓
3
設定画面 endpoint を見て種別アイコンを付けて表示する

5-2. 1件削除

1
設定画面「削除」ボタン → invoke('delete_push_device', { device_id })
↓
2
Rust Drive から push_devices.json を取得 → device_id に一致するエントリを除外 → Drive に書き戻す
↓
3
devices が空になった場合は push_devices.json ごと削除する
↓
4
設定画面 一覧から該当行を取り除く（再取得はしない、楽観的更新）

5-3. 全件削除

1
設定画面「全件削除」ボタン → 確認ダイアログ → invoke('delete_all_push_devices')
↓
2
Rust Drive から push_devices.json を削除する
↓
3
設定画面 一覧を空にする
全件削除すると次回 PC から Push を送っても届かない。iPhone 側で再セットアップ（push 画面で「通知を許可する」）が必要になる。
