viewer/page.tsx の参照関係、各フック・ライブラリの役割、および iPad 等複数端末への Push 配信の仕組みを説明する。

2. 各ファイルの役割一覧
ファイル役割外部依存
viewer/page.tsx PWA ルート。step 状態を管理し、各画面コンポーネントを切り替える —
hooks/useAppInit.ts 起動時の一度だけ実行される初期化。SW 登録・OAuth コールバック処理・pending_open チェック・step 初期遷移を担う Vercel /api/auth/token
hooks/useNoteList.ts step=list になるたびに Drive から notes_to_iphone.json を取得し IndexedDB にマージ。処理済みファイルは即削除 Drive API / Vercel /api/auth/refresh
hooks/useLockToggle.ts 🔔 ON/OFF。ON 時は SW 経由で通知を表示し locked: true を IndexedDB に保存。OFF 時は通知を閉じ locked: false を保存 ServiceWorker（通知表示）
lib/drive.ts Google Drive API のラッパー。全関数が token 期限切れ時に /api/auth/refresh を呼んで自動リトライ Drive API / Vercel /api/auth/refresh
lib/push.ts > subscribePush 通知許可取得 → Web Push サブスクリプション → push_devices.json に endpoint を upsert（複数端末対応） Drive API
lib/auth.ts PKCE 生成・OAuth リダイレクト・バイナリ変換ユーティリティ —
lib/indexeddb.ts IndexedDB (fusen-drafts) の読み書き。UI の唯一の真実のデータ源（SSOT） —
worker/index.js（SW） Push 受信 → 画像ダウンロード → IndexedDB 保存 → Drive 削除 → 通知表示。notificationclick でノートを開く Drive API（IndexedDB 経由で token 取得）
app/api/auth/token/route.ts OAuth 認証コード → アクセストークン交換。GOOGLE_CLIENT_SECRET_PWA を使うため Vercel に置く（ブラウザに秘密鍵を渡さないため） Google OAuth2 API
app/api/auth/refresh/route.ts リフレッシュトークン → アクセストークン更新。同上の理由で Vercel に置く Google OAuth2 API
3. なぜ Vercel に API を置くのか

Google OAuth のトークン交換・更新には client_secret（秘密鍵）が必要。 この鍵をブラウザ（iPhone）に渡すとユーザーが盗み見できるため、 Vercel のサーバー側 API Route に隠して置く。 iPhone はサーバーを経由してのみトークンを取得できる。

iPhone → Vercel API → Google OAuth2
iPhone が直接 Google に client_secret を送ることはない。 Vercel が中継することで秘密鍵を保護する。
4. マルチデバイス Push の仕組み（iPhone + iPad）
鍵概念 Push の宛先（endpoint）は push_devices.json に配列で保存される。 端末ごとに device_id と endpoint が 1 エントリ。 PC は全エントリに対して Push を送る。
push_devices.json の構造：

{
  "devices": [
    { "device_id": "abc-111", "endpoint": "https://api.push.apple.com/...", "keys": {...} },
    { "device_id": "xyz-222", "endpoint": "https://api.push.apple.com/...", "keys": {...} }
  ]
}

iPad を追加する手順

1
iPad で PWA を Safari から開き、ホーム画面に追加する（banner 画面）
↓
2
iPad で Google ログインする（login 画面）
useAppInit → /api/auth/token → access_token + refresh_token 取得 → localStorage に保存
↓
3
iPad で「通知を許可する」を押す（push 画面）
subscribePush → iPad の endpoint を生成 → push_devices.json を Drive から読んで iPad の エントリを upsert（追記）→ Drive に書き戻す
↓
4
push_devices.json に iPhone と iPad の 2 エントリが存在する状態になる
↓
5
PC から「iPhoneに送る」を実行
Rust (PC) → push_devices.json を読む → devices 配列の全エントリにループして Push 送信
iPhone の endpoint にも、iPad の endpoint にも、同じ内容の Push が飛ぶ
↓
6
iPhone の SW と iPad の SW が、それぞれ独立して Push を受信し、IndexedDB に保存、通知を表示する
注意点
・同じ Google アカウントでログインする必要がある（Drive を共有するため）
・IndexedDB は端末ごとに独立しているので、各端末が個別にノートを保持する
・iPad で push セットアップを完了しなくてもフォールバックが働く：list 画面を開いたとき notes_to_iphone.json が Drive にあればそこから読んで表示される（通知は来ないが内容は見える）
5. 起動時の step 遷移（useAppInit の全ケース）
起動時の状態遷移先 step
非 standalone（Safari で開いた） banner（ホーム画面追加案内）
URL に ?code=（OAuth コールバック） /api/auth/token でトークン取得 → push
URL に ?note=（通知タップで起動） IndexedDB からノート読み込み → write
token あり・pending_open あり（30分以内） IndexedDB からノート読み込み → write
token あり・push 設定済み（viewer_push_done=true） write（通常起動）
token あり・push 未設定 push（通知セットアップ）
token なし login
