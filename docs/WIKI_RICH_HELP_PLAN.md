# ユーザー向けリッチヘルプサイト化計画

## 方針

ユーザー向けヘルプ本体は、GitHub Wiki の素の Markdown ではなく、設計書ポータル風のリッチな docs サイトとして作る。

- ヘルプ本体: `docs-v2/` の VitePress 側に新設する。
- GitHub Wiki: リッチヘルプサイトへの入口にする。
- repo 側 `docs/100_USER_GUIDE.md`: 古いリンク救済の薄い案内板として維持する。

## 目的

- ユーザーが「読む」より先に「どこを押せばいいか」分かるヘルプにする。
- 設計書ポータルと同じ品質感で、カード、導線、色付きセクション、画像を使う。
- 初心者、困っている人、使い込みたい人が別々の入口から入れるようにする。

## まず確認すること

1. `docs-v2/` の VitePress 構成
2. 既存サイドバーとナビゲーション
3. ユーザー向けページを設計書と同居させるか、別セクションにするか
4. 画像や漫画素材の置き場所
5. GitHub Pages での公開URL

## デザイン方針

- 設計書ポータルと同じVitePress上に置く。
- ただし開発者向け設計書とは入口を分ける。
- カード型の目的別導線を使う。
- 注意事項は callout で目立たせる。
- スクリーンショットや漫画画像を積極的に使う。
- 文章は短く、操作順を中心にする。

## Wiki 側の扱い

GitHub Wiki は詳細ヘルプ本体にしない。

- Home に「最新ヘルプはこちら」とリッチヘルプサイトへの導線を置く。
- 既存の章ページは、必要なら旧ヘルプ・簡易版として残す。
- 最終的には Wiki から docs-v2 ヘルプへ誘導する。

## 実装順

1. `docs-v2/` の構成を確認する。
2. ユーザーヘルプの配置場所とURLを決める。
3. VitePress のナビ / サイドバー追加方針を決める。
4. ヘルプトップを作る。
5. 各章ページを作る。
6. 画像・漫画素材を接続する。
7. Wiki Home と `docs/100_USER_GUIDE.md` をリッチヘルプサイトへ誘導する形に直す。
8. `npm run docs:build` で確認する。
9. ブラウザで表示確認する。
10. repo側をコミットする。
11. 必要なら Wiki 側も別コミットして push する。
