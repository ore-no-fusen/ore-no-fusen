🐛 1. 現状の問題（バグの根本原因）

🔴 致命的: 画像が一覧↔編集の往復で壊れる

原因: ドラフトをIndexedDBから読み込む際、blobMap: new Map() として空で渡している。 つまり画像Blobはインメモリから消える（IndexedDBには残っているが読み込んでいない）。
場所: loadDraft(id).then(draft => setPendingHydrate({ blobMap: new Map() }))（742行・764行）
修正方針: ドラフト読み込み時に images を blobMap に変換して渡す。

🔴 致命的: ロック通知を押すと違うデータが出る（可能性）

原因: すでに write 画面でメモAを開いている状態で、ロック通知（メモB）をタップすると、 アプリが再起動せずURLだけ変わる。初期 useEffect([], []) は再実行されないため、メモBのデータが読み込まれない。
場所: useEffect(..., [])（656行） — 初回マウント時のみ実行
修正方針: URLの ?note= を購読し、変化したときに再ロードする。

🟠 中: ロック状態の二重管理

lockedNoteIds（IndexedDBから読む）と activeNotifIds（SWから読む）の2つがある。 どちらがONかによってベルのUIが変わるが、タイミングによってズレが生じ、 ベルがONなのに通知が出ていない・逆の状態になる。
修正方針: lockedNoteIds（IndexedDB）を唯一の真実とする。activeNotifIds は廃止。

🟠 中: list useEffectが毎回BlobURLを作り直す

useEffect([step]) に依存しているため、step が変わるたびに サムネイルのBlob URLを全件作り直す。write→list→write→listで4回実行される。 CleanupでrevokeしているがタイミングによってはUI上に壊れた画像が一瞬表示される。
修正方針: ListScreenを独立コンポーネントにする。マウント時のみ実行。

🟡 軽微: 死んだコード・型

noteData state、step='note'、downloadWithAutoRefresh（notes_to_iphone.json固定）が残っている。 コードを読む人を混乱させる。削除対象。

🟡 軽微: 30個の state が1コンポーネントに同居

認証・編集・一覧・ロック・画像・Mermaid・タグ・トースト通知の state が全部 ViewerPage() に入っている。1つの state 変化が無関係な再レンダリングを起こす。

📐 2. 設計ルール（変えない原則）

①

IndexedDB が唯一の真実

メモの内容・画像・タグ・locked状態 は すべて IndexedDB が正しい。 メモリ上の state は IndexedDB の「表示用キャッシュ」にすぎない。 画面遷移が起きたら IndexedDB から再読み込みする。state を source of truth にしない。

②

画像 Blob は IndexedDB から毎回読む

URL.createObjectURL() で作った URL は「表示のためだけ」に使い、 使い終わったら revokeObjectURL() する。 コンポーネント間で Blob URL を state 経由で渡さない。 編集画面に遷移するときは、必ず IndexedDB の images から blobMap を作り直す。

③

URL パラメータは購読する

?note=id はロック通知タップでいつでも変化しうる。 初回 useEffect([], []) だけでなく、popstate イベントと visibilitychange でアプリがフォアグラウンドに戻ったときにも確認する。 これで「すでに開いているときに別の通知をタップ」が正しく動く。

④

ロック状態は IndexedDB のみ。SW は「実行係」

lockedNoteIds を IndexedDB の locked === true から作る。 activeNotifIds（SWからのGET_NOTIFICATIONS）は廃止する。 SW は「通知を出す/消す」だけの実行係。状態を管理しない。
