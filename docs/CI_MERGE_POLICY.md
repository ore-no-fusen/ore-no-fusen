# PC中心の統合と検査

|対象|運用|
|---|---|
|PC内の修正|作業ワークツリーで必要な対象確認後、PCのdevelopへ統合|
|PC外の修正|PRで内容と確認結果を読み、採用分をPCへ取り込んで未確認の影響箇所を確認|
|GitHubへの保存|ソースと確認記録を保存。push・PR・統合で同じ検査を自動再実行しない|
|必要なGitHub検査|手動実行。Testには比較元の完全なSHAを指定。失敗・取消・不明を合格扱いしない|
|リリース候補|PCで候補を固定し全体確認。合格記録と同じexeをStoreへ引き継ぐ|
|履歴保護|main/developの削除・force push防止を維持。PR/CI必須を統合の条件にしない|
