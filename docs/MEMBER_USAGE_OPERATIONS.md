# 会員別・全体の週次機能利用状況を見る

対象はGA4プロパティ `ore-no-fusen`。アプリは会員番号をGA4へ送らず、ランダムな分析IDをUser-IDとして使用する。会員番号との照合が必要な場合だけFirestore会員台帳の対応を管理者が参照する。

## 全体傾向

1. GA4の「探索」で自由形式を作成する。
2. ディメンションへ「集計対象週」「利用した機能」を追加する。
3. 指標へ「週間使用回数」「週間使用日数」「総ユーザー数」を追加する。
4. 行を「利用した機能」、列を「集計対象週」、値を「週間使用回数」と「総ユーザー数」にする。
5. `weekly_feature_usage` だけを対象にする。

使用回数だけで順位を決めず、利用者数と使用日数も併記する。特定の少人数による大量使用と、多数の利用者による定着を区別するためである。

## 個別傾向

1. GA4の「探索」でユーザーエクスプローラを開く。
2. 対象のUser-IDを選ぶ。
3. `weekly_feature_usage` を「集計対象週」「利用した機能」で表示する。
4. 「週間使用回数」「週間使用日数」「最終使用日」を確認する。

個人名は表示しない。問い合わせ対応などで会員番号との照合が必要な場合だけ、管理者専用の `POST /api/members/lookup` を使用する。本文へ `environment` と `generalNumber`、AuthorizationヘッダーへVercelに保存した `MEMBER_REPORT_TOKEN` を渡すと、該当するGA4 User-ID、登録日時、有料番号（未導入時はnull）だけを返す。利用履歴は返さず、利用者の通常操作からこのAPIは呼ばれない。

この照会は会員番号を1件ずつFirestoreの番号索引から直接検索するため、登録者全員を読み込まない。分析時に管理者が必要なときだけ実行する。

## 数値の扱い

- `weekly_usage_complete` を受信した分析IDだけを、その週の分析対象者とする。
- イベントがない利用者を「未使用」と断定しない。未同意、未起動、送信失敗の可能性がある。
- 「未使用」は週次完了があり、対象機能の行がない場合に判定する。
- GA4のカスタム定義は登録後のデータに適用され、画面へ反映されるまで時間がかかる場合がある。
