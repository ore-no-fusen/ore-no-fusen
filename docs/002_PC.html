🖥 1. 画面構成

PCアプリはメインウィンドウ1枚＋付箋ウィンドウN枚のマルチウィンドウ構成です。

PC アプリは Tauri のマルチウィンドウ構造。メインウィンドウ1枚 ＋ 付箋ウィンドウ N 枚が独立して動く。ウィンドウ間の状態共有は Rust の AppState のみを通す。フロントエンドに状態を持たない。

🏠 メインウィンドウ

アプリの司令塔。ユーザーには見えないことが多い（トレイ常駐）。

・起動時に付箋ウィンドウを生成・配置する
・設定画面・検索オーバーレイを表示する
・トレイアイコンのイベントを受け取る
・iPhone からの受信（ポーリング）を担当する

app/page.tsx

📝 付箋ウィンドウ（N 枚）

付箋1枚ごとに独立した WebviewWindow。

・テキスト編集（RichTextEditor）
・最小化（たたむ）・ピン留め・色変更
・右クリックメニュー（iPhone送信・アーカイブ等）
・画像キャプチャ・リンク挿入

app/components/StickyNote.tsx

2.2 バックエンド（Rust）

TauriコマンドとAppStateを中心とするRust側モジュールの役割を一覧します。

ファイル 役割 主な責務
main.rs エントリポイント Tauri アプリ起動・プラグイン登録・シングルインスタンス制御
lib.rs invoke ハンドラ定義 フロントエンドから呼ばれる全コマンドをここで宣言。処理は各モジュールに委譲
state.rs AppState（唯一の状態） ノート一覧・設定・VAPID鍵・デバイス情報をメモリ上で保持。Mutex で排他制御
settings.rs 設定管理 base_path・言語・フォントサイズ等を settings.json に読み書き
logic.rs 付箋ビジネスロジック ノート作成・保存・リネーム・アーカイブ・削除・タグ管理
storage.rs ファイル I/O Markdown ファイルの読み書き・frontmatter パース
tray.rs トレイアイコン トレイメニュー生成・全表示/全隠し・クリックイベント処理
webpush.rs プッシュ通知送信 VAPID 鍵生成・APNs/FCM への Web Push 送信
gdrive.rs Google Drive 連携 Drive ファイルの読み書き・ポーリング（iPhone からの受信検出）
capture.rs 画像キャプチャ Snipping Tool 起動・クリップボード画像を assets/ に保存
clipboard.rs クリップボード テキスト・画像のクリップボード読み書き
sound.rs 効果音 保存音・通知音などの再生
import.rs ファイルインポート 外部 Markdown ファイルを Vault に取り込む
logger.rs ログ デバッグログの出力管理
📦 3. データ構造

付箋ファイル・設定ファイル・モジュール依存の3種類のデータ構造を定義します。

3.1 付箋データ（Markdown ファイル = frontmatter + 本文）

付箋1枚 = Markdown ファイル1枚。PC ローカルのファイルシステムが正。Drive は中継所に過ぎない。

フィールド型意味
pathstringファイルパス（実質的な主キー）
contentstring本文テキスト（Markdown）
contextstringコンテキスト名（ファイル名。本文1行目から自動生成）
updatedstring最終更新日時
x, ynumber画面上の位置座標
width, heightnumberウィンドウサイズ
background_colorstring付箋の背景色
always_on_topboolean最前面固定（ピン留め）
foldedboolean折りたたみ状態（最小化）
seqnumber重なり順（Z-index 相当）
tagsstring[]タグ一覧
3.2 設定データ（settings.json）

settings.json で管理するアプリ全体の設定項目5点を定義します。

フィールド型意味
base_pathstringVault フォルダのパス（未設定なら初回セットアップ画面）
languagestring表示言語
auto_startbooleanOS 起動時に自動起動するか
font_sizenumber基本フォントサイズ
sound_enabledboolean効果音 ON/OFF

🔄 4. データフロー

アプリ起動から保存・画像・検索・iPhone連携まで6つのシーケンス図を示します。

4.1 アプリ起動

起動時にファイルシステムから付箋一覧を読み込むフローです。

sequenceDiagram participant User as ユーザー participant Rust as Rust (main.rs) participant Page as page.tsx participant Win as 付箋ウィンドウ User->>Rust: アプリ起動 Rust->>Page: WebView 初期化完了 Page->>Rust: fusen_get_state() Rust->>Rust: settings.json + Vault スキャン Rust-->>Page: AppState（ノート一覧） alt base_path 未設定 Page->>Page: セットアップ画面表示 (900x630) User->>Page: フォルダ選択 Page->>Rust: setup_first_launch() else 設定済み Page->>Page: ダッシュボード表示 (240x300) end loop 前回開いていた各ノート Page->>Win: WebviewWindow 生成 (x, y, width, height) end
4.2 付箋の保存・自動リネーム

本文の1行目をファイル名（context）として自動採用する。800ms のデバウンスで連続入力に追従。

sequenceDiagram participant Editor as RichTextEditor participant Logic as logic.rs participant FS as ファイルシステム Editor->>Editor: テキスト変更 Editor->>Logic: 800ms デバウンス後に発火 Logic->>Logic: 1行目からファイル名生成 Logic->>FS: rename() 実行 FS-->>Logic: 新しいパスを返す Logic->>Editor: path 更新通知
4.3 画像キャプチャ

OS 内蔵の Snipping Tool を呼び出し、撮影された画像を Vault の assets/ に自動保存する。

sequenceDiagram participant User as ユーザー participant Fusen as 付箋ウィンドウ participant Snip as Snipping Tool participant FS as assets/ フォルダ User->>Fusen: 📷 ボタンをクリック Fusen->>Fusen: 全付箋を一時非表示 Fusen->>Snip: 起動 User->>Snip: 範囲選択して撮影 Snip->>Snip: クリップボードに画像をコピー Fusen->>FS: assets/ へ画像ファイルとして保存 Fusen->>Fusen: Markdown に画像リンクを挿入 Fusen->>Fusen: 全付箋を再表示
4.4 全文検索

キーワードをリアルタイムで全付箋から検索するフローです。

sequenceDiagram participant User as ユーザー participant Page as page.tsx participant Search as SearchOverlay participant Rust as Rust participant Target as 付箋ウィンドウ User->>Page: Ctrl+F / トレイ「検索」 Page->>Page: 検索オーバーレイ表示 (550x450) User->>Search: キーワード入力 + Enter Search->>Rust: fusen_search_notes("keyword") Rust->>Rust: Vault 内 .md ファイルを全文 Grep Rust-->>Search: SearchHit[]（ファイルパス・行番号） Search->>User: 結果リスト表示 User->>Search: 結果をクリック Search->>Target: emit('fusen:scroll_to_line', {path, line, query}) Target->>Target: 該当行にスクロール＋ハイライト
4.5 iPhone への送信（PC → iPhone）

PCの付箋内容をWeb Pushでiphone通知として届けるフローです。

sequenceDiagram participant User as ユーザー participant PC as PC アプリ participant Drive as Google Drive participant Push as APNs / FCM participant iPhone as iPhone SW User->>PC: 右クリック →「iPhone に送る」 PC->>Drive: notes_to_iphone.json を書き込み PC->>Push: Web Push 送信（VAPID 認証） Push->>iPhone: 通知を配信 iPhone->>Drive: notes_to_iphone.json を取得 iPhone->>iPhone: IndexedDB に保存 iPhone->>Drive: notes_to_iphone.json を削除 iPhone->>User: 通知表示
Drive 設計原則：送信後 Drive に JSON が残っている = まだ iPhone が受け取っていない。受け取ったら即削除。
4.6 iPhone からの受信（iPhone → PC）

iPhoneから送られたメモをPCアプリで付箋として受け取るフローです。

sequenceDiagram participant Drive as Google Drive participant Rust as gdrive.rs (30秒ポーリング) participant Page as page.tsx participant Win as 新規付箋ウィンドウ loop 30秒ごと Rust->>Drive: notes_from_iphone.json を確認 alt 新着あり Drive-->>Rust: ノートデータ + 画像ファイル名 Rust->>Page: emit('fusen:from_iphone', data) Page->>Win: 新規 WebviewWindow 生成 Rust->>Drive: 処理済みアイテムを削除 Rust->>Drive: 画像ファイル (fusen_img_*.jpg) を削除 else 新着なし Rust->>Rust: 何もしない end end
重複受信防止：last_seen_id でスキップ。Drive に残っていても同じ ID は2度開かない。
🖱 5. UI インタラクション

付箋ウィンドウの操作領域・モード・マウス挙動を定義します。

付箋ウィンドウには 表示モード（閲覧中） と 編集モード（執筆中） の2状態がある。 クリックした場所と現在のモードの組み合わせで動作が決まる。
5.1 モード定義

表示・編集・ロックの3モードとその遷移条件を定義します。

モード状態
表示モード（閲覧中） Markdown としてレンダリング済みの付箋を読んでいる状態
編集モード（執筆中） カーソルが点滅し文字を書き込める状態。背景が半透明の白になる
stateDiagram-v2 [*] --> ViewingMode : 表示モード ViewingMode --> EditingMode : ダブルクリック（本文・余白・フッタ） EditingMode --> ViewingMode : 編集終了（ウィンドウ外 or フッタクリック）
5.2 操作領域の定義

付箋ウィンドウをエディタ本文・余白(A)・フッタ(B)の3エリアに分けて操作を割り当てます。

領域場所ユーザーの意図
エディタ本文 文字・リンクが実際に存在する場所 「ここを直接操作・書き換えたい」
(A) エディタ余白 文字の右側・左側に広がる枠線内の空白 「この行の続きや近くから書き込みたい」
(B) フッタ領域 最後の行より下にある何もない空間（エディタ外） 「一番下から追記したい」または「編集を終わらせたい」
5.3 インタラクション・マトリックス

エリア × 操作の組み合わせで起きる動作を一覧にまとめます。

🖱 ワンクリック

クリックした場所表示モード編集モード
エディタ本文何もしない（ドラッグ準備）カーソル移動（その文字へ）
(A) エディタ余白何もしない（ドラッグ準備）カーソル移動（最近傍の文字へ）
(B) フッタ領域何もしない（ドラッグ準備）編集終了
リンクリンクを開くカーソル移動
ウィンドウ外フォーカス解除編集終了（保存して表示モードへ）

🖱🖱 ダブルクリック

クリックした場所表示モード編集モード
エディタ本文編集開始（クリックした文字から）単語選択
(A) エディタ余白編集開始（最近傍の文字から）—
(B) フッタ領域編集開始（文末から）—

✋ ドラッグ（押しっぱなしで移動）

ドラッグした場所表示モード編集モード
エディタ本文🪟 ウィンドウ移動📝 テキスト範囲選択
(A) エディタ余白🪟 ウィンドウ移動🪟 ウィンドウ移動
(B) フッタ領域🪟 ウィンドウ移動🪟 ウィンドウ移動
右クリック：表示モードでは閲覧用メニュー（削除・色変更等）、編集モードでは編集用メニュー（コピー・貼り付け等）が開く。
Ctrl + クリック：編集モード中でもリンクを強制的に開く。
