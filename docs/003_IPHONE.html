📱 1. 画面構成

iPhone PWA は step state で切り替わる5画面の単一ページアプリです。

iPhone PWA は page.tsx 内の step state で表示画面を切り替える単一ページアプリ。 step の値は5種類：banner / login / push / list / write。 URLバーなしのネイティブアプリ風で動作する（PWA起動時）。

2.3 サーバーサイド（Vercel API Routes）

Google OAuth2 の client_secret を保護するVercel APIエンドポイント3点を説明します。

Google OAuth の client_secret（秘密鍵）をブラウザ（iPhone）に渡さないため、 トークン交換・更新の処理だけ Vercel のサーバーサイドに置く。iPhone は Vercel 経由でのみトークンを取得できる。

表 3-3　Vercel API Routes 一覧

ファイル役割
app/api/auth/token/route.ts OAuth 認証コード → アクセストークン＋リフレッシュトークン交換。初回ログイン時のみ呼ばれる。
app/api/auth/refresh/route.ts リフレッシュトークン → 新しいアクセストークン取得。Drive API 呼び出し時にトークン期限切れを検出したら自動呼び出し。
📦 3. データ構造

IndexedDB・localStorage・Google Drive の3か所にデータを分散して保存します。

データの正：表示データの唯一の真実（SSOT）は IndexedDB（fusen-drafts）。 Drive は中継所（未処理キュー）に過ぎない。Drive に残っているものは「まだ処理していない」を意味する。処理済みは即削除。

3.3 Google Drive ファイル

PCとiPhone間の中継に使うDriveファイルの種類と書き込み/削除責務を説明します。

Drive 設計原則：Drive にあるものは全て未処理キュー。処理済みは即削除。 状態フィールド（received_at 等）は不要。残っていたら削除 API 失敗の残骸。

表 3-8　Google Drive ファイル一覧

ファイル名書き込み読み取り・削除意味
notes_to_iphone.json PC（gdrive.rs） iPhone SW（push受信時） PC → iPhone 未処理キュー。SW が受信して IndexedDB に保存後、当該 ID を除いて書き戻す（または全削除）。
notes_from_iphone.json iPhone（useBackgroundSend） PC（gdrive.rs 30秒ポーリング） iPhone → PC 未処理キュー。PC 受信後は処理済みアイテムを除いた残りのみ書き戻す。
fusen_img_*.jpg iPhone（useBackgroundSend）または PC（gdrive.rs） 受信側が処理後に削除 添付画像ファイル。ファイル名規則: fusen_img_YYYYMMDD_HHMMSS_コンテキスト_N.jpg
push_devices.json iPhone（lib/push.ts）が upsert PC（webpush.rs）が読んで全端末へ Push 送信 Web Push の宛先一覧。端末ごとに device_id / endpoint / keys を保持。複数端末（iPad 等）対応。

4.4 ロックだぜ ON/OFF と再通知サイクル（REQ_IP_05）

「消す意思がないかぎりロック画面から消えない」体験を実現する ON/OFF 操作と、タップ後の再通知サイクル。 ユーザー体験の手順は ①〜⑥ で示す（REQ_IP_05 の①〜④に対応）。

sequenceDiagram actor UserPhone as ユーザー（iPhone） box iPhone PWA participant PWA as 2⃣ iPhone PWA（list画面） end box Service Worker participant SW as 3⃣ Service Worker end Note over SW,UserPhone: ①〜③ 常駐サイクル（locked: true が前提） SW->>UserPhone: ① 🔔 ロック画面に通知を表示（push受信時） UserPhone->>SW: ② 通知をタップ（notificationclick） SW->>SW: IndexedDB で locked 確認 → true SW->>UserPhone: 🔔 通知を再表示（ロック画面から消えない） SW->>PWA: OPEN_NOTE メッセージ または openWindow PWA->>UserPhone: ③ 付箋の内容を表示 Note over SW,UserPhone: ④ ①〜③ を繰り返す Note over PWA,UserPhone: ⑤ ユーザーが明示的に OFF にする UserPhone->>PWA: 🔔 ボタンをタップ（list画面） alt locked: false → ON にする PWA->>PWA: IndexedDB に locked: true を保存 PWA->>SW: showNotification（通知を出す） SW->>UserPhone: 🔔 ロック画面に通知が常駐する else locked: true → OFF にする PWA->>PWA: IndexedDB に locked: false を保存 PWA->>SW: getNotifications → close() SW->>UserPhone: ⑥ 🔕 ロック画面の通知が消える end

図 3-6　ロック画面常駐サイクル（ON/OFF と再通知）

通知を消せるのは SW だけ：一度表示した通知を非表示にするには registration.getNotifications() で取得して n.close() を呼ぶ必要がある。 useLockToggle は SW へのメッセージ送信でこれを実現する。
locked の初期値：push 受信時に IndexedDB へ保存するとき locked: true で保存する（SW の saveToIndexedDB）。 これにより、ユーザーが 🔔 ボタンを操作する前から ①〜③ のサイクルが有効になる。
