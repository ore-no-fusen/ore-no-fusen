# 修正結果のキャプチャ報告

画面・設計書の修正結果は、追加依頼を待たずキャプチャと固定リンクで返す。証拠として出す画像は実際に起動した対象ページ・アプリをそのまま撮影する。別ファイルへの抜粋・見出し追加・HTML再構成を、実画面の証拠として使わない。

表1：標準手順

|順序|実施すること|
|---|---|
|1|変更した箇所を撮影。表番号・行番号・日本語の概要を読める範囲にする。|
|2|PNGを目視し、修正の反映・切れ・公開してよい内容かを確認。|
|3|既存の画像専用共有先へ保存し、HTTP成功と画像形式を確認。|
|4|最終返信にクリックできる固定リンク、URL単独行、画像を残す。|

## 文書修正と利用者確認

表3：設計書を修正するときの確認手順

|番号|段階|確認すること|
|---|---|---|
|1|修正前|文書の目的・正本・変更する既存の項目を確認し、目的と配置理由をCURRENTに記録する。|
|2|配置|設計書には現在の構造・仕様・継続する方針とその理由を置く。今回の実施件数・結果・残作業はCURRENTに置く。|
|3|反映|機能やテストの追加・削除は元の一覧を更新する。報告用の別表で代用しない。|
|4|差分確認|作業報告の混入、一覧との不整合、必要な考え・理由の欠落を確認する。「今回」「追加した」「実施した」は混入を探す手掛かりであり、一律削除の条件にしない。改版履歴は別扱い。|
|5|実画面|変更した実ページを加工せず撮影し、読める範囲ごとに固定HTTPSリンクを提示する。削除した場合は前後の項目がつながる箇所を示す。|
|6|利用者確認|「修正・自己確認済み」と「利用者確認済み」を区別する。利用者の返答が来るまでは確認待ちと記録し、無回答を了承にしない。指摘は元の資料へ反映して新しいキャプチャを提示する。|

提示は「①何を確認する画面か」の一言を添え、複数箇所は1枚ずつ分ける。一覧の更新は該当行、削除は前後のつながりを撮影し、変更箇所の写っていない画像で代用しない。確認できない内容は未確認と示す。動く機能は、必要な対象試験の結果も短く添える。

自己確認だけで利用者の意図に合うと断定しない。利用者確認待ちは、許可済みの対象確認・develop統合を再承認制に変えるものではない。キャプチャは見える内容の証拠であり、動作試験の代わりにはしない。

## コマンド

```powershell
# 直近の確認済みリンクを即座に再提示（通信・再撮影なし）
node scripts/capture-result.cjs --last
# 設計書は既存のVitePressで実ページを開いて撮影
node scripts/capture-result.cjs --url http://127.0.0.1:5173/ore-no-fusen/004_TEST#test-traceability
# アプリは既存の起動方法で開いた実画面を撮影
node scripts/capture-result.cjs --url http://localhost:3002
# 目視済み・公開可能なPNGを共有。最後に返信用Markdownを出力
node scripts/capture-result.cjs --image "撮影されたPNGの絶対パス" --share
```

`--selector CSS`で変更箇所を絞り、`--height 1120`で縦幅を指定する。単体プレビュー用の`--file`は下書き確認用に限り、実画面の証拠には使わない。PNGの隣に撮影元・版・日時、共有後は返信文を保存する。画像は内容ハッシュで命名し同じ画像を再登録しない。

表2：繰り返さない失敗

|状態|扱い|
|---|---|
|PCのローカル画像パスだけを返信|iPhoneに届いたと扱わない。|
|ツール内で一瞬表示された|最終返信の固定リンクを省略しない。|
|以前の画像URL|上書きしない。修正版は別URLを残す。|
|公開できない内容・共有失敗|公開や成功を装わない。公開可能な別手段を確認。|
|キャプチャのための全件試験|実行しない。撮影・表示・リンクだけ確認。|

既存共有先は公開GitHubの画像専用ブランチ `codex/キャプチャ画像の共有`。コードのmain/developやアプリ配信を変更しない。公開不可の情報は送らない。共有treeに別の変更があれば停止する。通信を含む所要時間は1秒保証ではない。準備済み画像の再提示は保存済みURLをそのまま返し、再撮影・再公開しない。
