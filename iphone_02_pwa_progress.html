3. Google OAuth ログインと Vercel の役割

なぜ Vercel が必要か： iPhone（PWA）は誰でもソースコードを見られる「公開クライアント」。 Google の client_secret をここに置くと全ユーザーに漏れる。 Vercel（サーバー）だけが秘密を持ち、代わりにトークン交換を行う。

{ code, code_verifier, redirect_uri } Note over PWA: client_secret は送らない（知らない） Vercel->>Google: POST /token
{ code, code_verifier, client_id, client_secret } Note over Vercel: client_secret をここで初めて使う Google->>Vercel: access_token（+ refresh_token） Vercel->>PWA: access_token を返す PWA->>PWA: access_token を localStorage に保存 Note over PWA: 以後の Drive 操作はこの token で直接行う end rect rgb(245, 230, 255) Note over PWA,Google: ④ Drive へのアクセス（Vercel を経由しない） PWA->>Google: Drive API（access_token を使って直接） Google->>PWA: fusen_note.json の内容 Note over Vercel: Vercel はもう関与しない end rect rgb(255, 240, 240) Note over PWA,Google: ⑤ アクセストークン自動更新（1時間ごと・再ログイン不要） Note over PWA: access_token が期限切れ（expires_at 経過） PWA->>Vercel: POST /api/auth/refresh { refresh_token } Vercel->>Google: POST /token { refresh_token, client_id, client_secret } Google->>Vercel: 新しい access_token Vercel->>PWA: 新しい access_token PWA->>PWA: access_token・expires_at を localStorage に上書き保存 PWA->>Google: Drive API（新しい access_token で再試行） Note over PWA: 6ヶ月間通知をタップしなかった場合のみ再ログインが必要 end
誰が持つ 鍵の名前 何のための鍵か 保存場所
PC VAPID秘密鍵 PCからiPhoneへ通知を送るときの「送信者証明」。Appleに「俺の付箋アプリからの正規通知」と証明する AppData\Local\ore-no-fusen\vapid_keys.json
（初回「iPhoneへ送る」時にDriveの ore-no-fusen/vapid_keys.json にも同期。別PCから送るときも同じ鍵を使えるようにするため）
PC Google リフレッシュトークン PCがDriveに付箋データを書き込むための長期パスワード。アクセストークン（有効期限1時間）が切れるたびにこれで新しいトークンを取得する AppData\Local\ore-no-fusen\gdrive_token.json
iPhone Google アクセストークン iPhoneがDriveから付箋データを読み込むための一時通行証（有効期限1時間） iPhoneのlocalStorage（viewer_access_token）
iPhone Google リフレッシュトークン iPhoneのアクセストークンが切れたとき、再ログイン不要で自動更新するための長期パスワード。6ヶ月未使用で失効 iPhoneのlocalStorage（viewer_refresh_token）
Vercel（サーバー） Google client_secret iPhoneのOAuthログインおよびトークン更新を仲介するための秘密の合言葉。これがないとGoogleがトークンを発行してくれない。もし漏れると、第三者が「俺の付箋アプリのふりをして」Googleにトークンを要求できてしまう。それを防ぐためVercel環境変数にのみ置き、ソースコードや通信には含めない Vercel環境変数（外部から見えない）
Vercel の負荷について：
/api/auth/token（初回ログイン）と /api/auth/refresh（トークン更新）が Vercel を経由する。 トークン更新はアクセストークンの有効期限（1時間）ごとに発生するが、通知をタップしたときだけ実行されるため、頻度は低い。 Vercel 無料枠（月10万リクエスト）を超える心配は当面ない。
